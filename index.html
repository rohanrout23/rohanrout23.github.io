CLASSICAL ML

Where it all begins

+

Focus on

Understand why a model works before touching sklearn. Master Linear/Logistic Regression, Decision Trees, Random Forest, KNN, SVM, Naive Bayes, and K-Means — plus data cleaning, feature engineering, and evaluation metrics. Real-world AI work is 70% data handling, not modeling.

Skip for now

Don't obsess over hyperparameter tuning frameworks or deep mathematical derivations before you understand the base algorithm and have built a few projects.

Mistake I made

I built models on messy datasets without properly understanding the data first — accuracy looked fine, but the model was learning noise. Spend more time understanding your data than tuning your model.

DEEP LEARNING

Moving beyond classical ML

+

Focus on

Perceptrons, activation functions, forward/backward propagation, and gradient descent — conceptually, before frameworks. Then CNNs, RNN/LSTM basics, and Transformers. Pick one framework (PyTorch is a good default) and go deep.

Skip for now

Don't try to master every architecture — GANs, Diffusion Models — before you're comfortable training a basic feedforward or CNN model end-to-end.

Mistake I made

I tried learning too many architectures at once without finishing one complete project. Build one full pipeline — data to deployment — before chasing the next architecture.

LANGCHAIN

Building with LLMs

+

Focus on

Prompts, Chains, Memory, and Retrievers cover 80% of real use. RAG is the single most practical skill right now — learn chunking, embeddings, vector storage (FAISS/Chroma), and retrieval. Then tool/function calling.

Skip for now

Don't get lost in every integration LangChain offers. Learn the pattern once with one vector DB and one LLM provider — it transfers everywhere else.

Mistake I made

I used pre-built chains without understanding what was happening inside them. Build a RAG pipeline manually at least once so you know what the abstraction is doing for you.

LANGGRAPH

From chains to agents

+

Focus on

The shift from linear pipelines to stateful, cyclical workflows. Understand nodes, edges, state management, conditional routing, and human-in-the-loop checkpoints — critical for production agent systems.

Skip for now

Don't build complex multi-agent systems on day one. Start with a single agent, 2-3 tools, and a simple decision loop.

Mistake I made

I underestimated state management — my agents lost context between steps. Get comfortable with how state flows through your graph before adding complexity.

IDEA

Most beginners don't need more courses — they need fewer

AUG 2026
+

Every week I talk to someone with 12 half-finished courses and zero shipped projects. The problem was never a lack of resources — it's decision fatigue. Pick one roadmap, ignore every other "must-watch" video for 30 days, and just build. You'll learn more from one messy finished project than from five polished course completions.

RESEARCH

Quick take: why RAG still beats fine-tuning for most use cases

AUG 2026
+

Fine-tuning feels like the "advanced" move, so beginners chase it early. In practice, most production use cases are better served by retrieval — it's cheaper, easier to update when your data changes, and doesn't require retraining every time something new comes in. Save fine-tuning for when retrieval genuinely can't solve your problem, not as a default first step.

GUIDANCE

How I actually evaluate if an agent framework is worth learning

AUG 2026
+

New agent frameworks show up constantly, and it's tempting to chase all of them. My filter: does it have real production adoption, active maintenance, and does it solve a problem my current stack genuinely can't? If the answer to any of those is no, I skip it — trend-chasing costs more time than it saves.
